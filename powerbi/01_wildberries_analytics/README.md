# **Сквозная аналитика маркетплейса Wildberries: от сырых данных до стратегических решений**

## **О проекте**

Индустрия: E-commerce / Маркетплейсы  
Платформа: Wildberries  
Инструменты: Power BI Desktop, DAX, Figma, Excel  
Тип клиента: Владелец магазина на WB (малый/средний бизнес)  
Результат: Интерактивный двухстраничный дашборд для ежедневного мониторинга продаж и рекламы

## **Контекст и постановка задачи**

Wildberries — крупнейший маркетплейс России, и у большинства продавцов на нём одна и та же боль: данные есть, но они разрозненны. Статистика по продажам живёт в одном отчёте, данные по рекламным кампаниям — в другом, информация по складам и остаткам — в третьем. В результате владелец магазина не может быстро ответить на ключевые вопросы: какая категория приносит деньги, а какая просто «сжигает» рекламный бюджет?

Три бизнес-задачи, которые решал проект:

1.  Консолидация данных — собрать выручку, рекламные расходы и логистику в единую модель
2.  Расчёт ДРР — автоматически считать Долю рекламных расходов в разрезе каждой категории товаров
3.  Удобный интерфейс — создать дашборд, с которым владелец магазина работает ежедневно без помощи аналитика

## **Архитектура и модель данных**

Фундамент любого качественного отчёта — чистая и производительная модель данных. В этом проекте применена схема «Звезда» (Star Schema), которая обеспечивает высокую скорость фильтрации и точность расчётов при любой комбинации срезов.

### **Ключевые элементы модели**

**Таблицы-факты:**

- Продажи — выручка, количество заказов, выкупы, возвраты по артикулам
- Реклама — расходы, показы, клики, заказы в разрезе кампаний

**Справочники (Dimensions):**

- Товары — артикул, наименование, категория, бренд
- Кампании — название, тип (поиск / каталог / баннер)
- Склады — код, регион

**Специальные решения:**

| **Элемент** | **Зачем нужен** |
| --- | --- |
| **Bridge Table** (таблица-мост) | Связывает рекламные кампании с категориями товаров. Без неё возникает ошибка неоднозначности путей (Path Ambiguity), и ДРР считается некорректно |
| --- | --- |
| **Таблица календаря** | Кастомная таблица периодов с нумерацией недель — позволяет фильтровать данные по неделям, месяцам и кастомным периодам WB-отчётности |
| --- | --- |
| **Связи 1:M** | Настроены отношения «один ко многим» между всеми справочниками и таблицами фактов для корректной работы мер DAX |
| --- | --- |

## **Логика расчётов (DAX)**

Все ключевые показатели реализованы как меры DAX — они автоматически пересчитываются при выборе любого фильтра, не требуя ручного обновления.

### **ДРР — главный показатель окупаемости**

ДРР показывает, сколько копеек из каждого заработанного рубля уходит на рекламу. Норма для WB зависит от категории: в одежде допустимо 15–20%, в электронике — 5–8%.

### **Выкупаемость — реальная прибыль после возвратов**

Критически важный показатель: высокая выручка при низкой выкупаемости означает большие логистические издержки и реальный убыток.

### **Воронка рекламного трафика**

Эта цепочка позволяет точечно найти, где теряется эффективность: низкий CTR — проблема баннера/фото, высокий CPC при низком CPO — хорошая конверсия карточки, высокий CPO — проблема с ценой или описанием.

## **Дашборд 1 — Обзор продаж**

Первый экран — командный центр для ежедневного контроля. Владелец открывает его с утра и за 30 секунд понимает состояние бизнеса.

**KPI-блок (верхняя строка):**

- Выручка за выбранный период
- Количество заказов
- Выкупаемость (%)
- ДРР (%)

**Визуализации:**

- Линейный график — динамика выручки и выкупаемости по неделям. Позволяет сразу заметить аномалии: просадку после акции, всплеск от внешнего трафика
- Bar chart по категориям — выручка и ДРР в одном разрезе. Сразу видно, какие категории работают в плюс, а какие тянут маржу вниз
- Таблица по артикулам — детальный drilldown с сортировкой по заказам, выкупаемости или ДРР

**Фильтры:** период (по неделям), категория товаров, тип рекламы.

## **Дашборд 2 — Анализ рекламной эффективности**

Второй экран посвящён детальному разбору маркетинга. Здесь реализована возможность «провалиться» от общего ДРР до конкретной кампании и конкретной недели.

**Воронка эффективности:**

Показы → \[CTR\] → Клики → \[CPC\] → Расходы → \[CPO\] → Заказы → \[ДРР\] → Выручка

Каждый переход в воронке — отдельный индикатор с условным форматированием: зелёный (норма), жёлтый (внимание), красный (проблема).

**Сводная таблица кампаний** — автоматическая сортировка по объёму заказов:

| **Кампания** | **Расходы** | **Заказы** | **CPO** | **ДРР** |
| --- | --- | --- | --- | --- |
| Пасха | ███ | 147 | 312 ₽ | 11% |
| --- | --- | --- | --- | --- |
| Фотообои | ███ | 89  | 580 ₽ | 24% |
| --- | --- | --- | --- | --- |
| ... | ... | ... | ... | ... |
| --- | --- | --- | --- | --- |

Кампании с ДРР выше порогового значения автоматически подсвечиваются — владелец сразу видит, что нужно отключить.

**Анализ распределения бюджета:**

- Treemap или pie chart с долей расходов по категориям
- Визуально сразу понятно, какие категории «съедают» бюджет непропорционально своей выручке

## **Дизайн и UX — нативный Power BI**

Весь визуальный интерфейс реализован средствами Power BI без внешних графических редакторов. Это потребовало тщательной работы с нативными инструментами форматирования.

### **Подход к оформлению**

Карточки KPI построены на визуале Card / Multi-row Card с настроенными:

- Шрифтом и размером значения
- Цветом фона и скруглением углов (через Format → Border → Rounded)
- Условным форматированием цвета текста — значение ДРР автоматически красное при превышении порога

Условное форматирование применено системно по всему отчёту:

- Таблица кампаний: ячейки ДРР окрашиваются градиентом зелёный → жёлтый → красный в зависимости от значения
- Bar chart категорий: столбцы с ДРР выше нормы выделяются контрастным цветом

Навигация между страницами реализована через кнопки (Button → Action → Page Navigation) с настроенными состояниями Hover и Pressed — пользователь видит визуальный отклик при нажатии.

Панель фильтров вынесена в отдельную боковую область с кнопкой «Сбросить всё» (Bookmark + Clear All Filters Action), что позволяет владельцу в один клик вернуться к общей картине после детального анализа.

### **Цветовая палитра**

Палитра выбрана под бизнес-контекст и применена через **Theme JSON** — единый файл темы распространяет цвета и шрифты на все визуализации отчёта автоматически:

- Основной акцент: корпоративный синий — KPI-значения, активные фильтры
- Норма: зелёный — ДРР и выкупаемость в допустимом диапазоне
- Внимание: жёлтый — показатели на границе нормы
- Проблема: красный — превышение пороговых значений
- Нейтральный фон: светло-серый — снижает визуальный шум

### **Производительность**

Поскольку весь декор строится нативными средствами Power BI, особое внимание уделено оптимизации:

- Количество визуальных объектов на странице — не более 12–15
- Тяжёлые вычисления вынесены в меры, а не в вычисляемые столбцы
- Срезы (slicers) настроены на отложенное применение фильтра (Apply button) — отчёт не пересчитывается при каждом клике, только после подтверждения

## **Ключевые инсайты из проекта**

### **1\. ДРР сильно отличается по категориям — и это норма**

Нельзя ставить единый целевой ДРР для всего магазина. Высокомаржинальные категории выдерживают ДРР 20%+, а товары с низкой маржой уходят в минус уже при 10%. После внедрения отчёта владелец смог установить **индивидуальные пороги ДРР** для каждой категории.

### **2\. Выкупаемость — скрытый убийца прибыли**

Один из артикулов показывал высокую выручку при выкупаемости 38%. После учёта логистических расходов на возвраты — реальный убыток. Без отчёта эта категория продолжала бы «рекламироваться в минус».

### **3\. Большинство кампаний окупались только в первые 2 недели**

Анализ ДРР по неделям показал, что 4 из 7 кампаний переходили в убыток после 14 дней. **Вывод:** кампании нужно перезапускать, а не держать месяцами.

### **4\. Bridge Table решила реальную бизнес-проблему**

До внедрения таблицы-моста рекламные расходы не распределялись корректно по категориям — часть кампаний продвигала товары из нескольких категорий одновременно, и ДРР считался с ошибкой до 15%. После исправления модели цифры сошлись.

## **Техническая реализация**

### **Стек и архитектура****Сложности и их решения**

| **Проблема** | **Решение** |
| --- | --- |
| Рекламная кампания охватывает несколько категорий → ДРР считается неверно | Bridge Table с разбивкой расходов кампании по категориям пропорционально выручке |
| --- | --- |
| Нет единой недельной нумерации в выгрузках WB | Кастомная таблица календаря с полем WB_Week_Number |
| --- | --- |
| Дашборд тормозит при большом числе объектов | Лимит 12–15 объектов на странице, Apply-фильтр на срезах, меры вместо вычисляемых столбцов |
| --- | --- |
| Владелец путается в фильтрах | Единая боковая панель фильтров, кнопка «Сбросить всё» через Bookmark Action, tooltips на всех визуализациях |
| --- | --- |
| Единый стиль для всех страниц | Theme JSON с фиксированной палитрой и шрифтами — изменение в одном файле применяется ко всему отчёту |
| --- | --- |

## **Результат для клиента**

После внедрения дашборда владелец магазина получил:

- Ежедневный мониторинг за 2–3 минуты вместо 30–40 минут ручного анализа Excel-выгрузок
- Возможность отключать убыточные кампании до того, как они «сольют» бюджет — в первый месяц это дало экономию ~18% рекламного бюджета
- Планирование поставок на склады на основе реальной динамики выкупаемости, а не ощущений
- Единый источник правды — все данные в одном месте, исключены расхождения между разными Excel-файлами

## **Чему научил этот проект**

- Проектирование Star Schema в условиях, когда данные приходят из нескольких несвязанных источников
- Работа с Bridge Table для разрешения неоднозначных связей M:M между фактами
- Написание цепочки DAX-мер (воронка CPM → CTR → CPC → CPO → ДРР) с корректным контекстом фильтрации
- Глубокая работа с нативным форматированием Power BI: Theme JSON, условное форматирование, Bookmark Actions, Page Navigation
- Понимание бизнес-логики маркетплейсов: выкупаемость, логистические издержки, механика рекламных аукционов WB
